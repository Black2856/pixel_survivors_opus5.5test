## 1. 同期の方式: ロックステップ

全員のブラウザが同じゲームを同じ乱数で計算し、送り合うのは毎フレームの入力だけにする。

- 各フレームは「全員のそのフレームの入力」がそろってから計算する。入力は数フレーム先の分として送る(入力の遅れ。#1)ので、回線が普通なら待たずに進む
- 送るもの: 移動の向き・E・Q・防御・照準の点・レベルアップのカードの選択。数十バイト / フレーム
- 演出・音・数字は、全員が同じ計算をするので、そのまま全員の画面に出る(送らない)
- 1秒ごとに状態のハッシュを送り合い、ずれ(デシンク)を見つける(#4)

この方式にした理由:
- 試験の道具(`scripts/dev/harness.js`)が、乱数の固定・setTimeout をゲームの時間で動かす・1/60 秒ずつ進める・描画の乱数を計算と分ける、をすでにやっていて、同じ入力なら同じハッシュになる。今の計算は、この方式の条件をほぼ満たしている
- ホストが計算して状態を送る方式は、描画(`render.js`・各ボスの描画)が敵の AI の中身まで読み、演出も計算の中で作っているので、送る物がほぼ世界全部になる

弱いところ:
- 操作が少し遅れる(#1)
- 1人の回線が詰まると全員が止まる(#3)
- 途中参加はできない(#12)
- 全員が全員の分を計算するので、4人だと 1人のときより重い(スマホが心配。8章)

## 2. 今のコードでの作り方

| 仕組み | 作り方 |
|---|---|
| プレイヤー | **3段で作った**: `players`(1〜4人。入った順で、ホストが 0。全員で同じ順)。`P` は「いま計算しているプレイヤー」で、計算の外では `players[0]`(自分)。1人ずつの処理(`updPlayer`・`updWeapons`・クラス)は `withPlayer` / `setP` で P を入れ替えて players の順に回す(乱数の引き方をそろえるため、順を変えない)。プレイヤーを作る処理は `makePlayer` / `setupPlayer`、2人目からは `addPlayer`(world.js) |
| 敵の狙い | **3段で作った**: 敵ごとに狙う人(`e.tPl`)を持ち、その敵を計算する間は P をその人にする(`enemyTarget`。#14)。敵の弾・床は作った敵の狙いを持ち(`tPl`)、動かすときも P をその人に。出たばかりの敵は、出した中心の人を狙う(#13) |
| 与えたダメージの記録 | **3段で作った**: 敵ごとに人ごとのダメージ(`e.aggro`)を `hitEnemy` の時の `P` に足す(2人以上の時だけ)。プレイヤーが作った弾・ゾーン・斬撃は作った人を持ち(`owned` → `pl`)、動かすときは P をその人に。後で起きる処理(`simTimeout`)も足した時の人で呼ぶ。燃焼は付けた人ごとにまとめて、その人で当てる。#14 の重みに使う |
| 拾うもの | **3段で作った**(2人以上の時だけ): 床の物は 1つ。毎フレーム、番号の小さい人から順に見て、先に届いた人が拾う。吸い寄せは、吸い寄せる範囲に先に入った人へ向かう(`to`)。ジェム・ゴールドは `P` を入れ替えて全員に `gainXP`・`addGold` を呼ぶ。#6 |
| 当たり判定 | **3段で作った**: 体当たりは全員と判定する。敵の弾・床・ボスの技は、狙っている人にだけ当たる(#25 の仮。全員に当てるには、床・技の種類ごとに「動かす」と「当たる」を分ける必要がある) |
| `S` にある 1人ずつの物 | **3段で移した**: kills・totalDmg・dmgBy・combo・comboT・bestCombo・gemStreak・gemStreakT・pendingLv・lvQueue・rerolls・weaponSlots・gold・deathT・decoy・bossKills・loot・cxpK・cxpB・stigmaT・flamePuffs・actId・dimK・eqLv を P へ(レベルアップの演出の時計は `P.lvUpT`)。ボスの撃破数・クラス経験値の元は全員に入る。まだ S にある、プレイヤーに関わる印は 8章 |
| 入力 | **2段で作った**: 計算が読む入力は 1人分の記録 `P.inp = { mx, my, e, q, def, aim, autoE, autoQ }`(`core.js` の `readInput`)だけ。計算 1回ごとに `update(rdt, inp)` が入れ、計算は `keys`・`touch`・`mouse`・`SET.autoE / autoQ` を直接読まない。E・Q の押した印は `P.wantE / wantQ` に残してスキルの処理が使い切る(ヒットストップの間に押しても消えない)。照準 `aim` はワールドの座標。スキルの自動発動の設定も記録に入るので、途中で変えても全員に同じに届く。カメラの先読みだけは今の入力のまま(見た目)。協力プレイではこの記録を送り合う。レベルアップのカードの選択(`pick`)は 5段で足す |
| ステータス | 参加の時に各自の クラス・クラスLv・武器・強化ツリー・装備 を送り合い、全員が全員のステータスを計算する(`applyStats` を「その人のセーブ」で) |
| レベルアップ | 止まらない画面(#8)。カードの選択は入力として送り、全員が同じフレームで適用する |
| 描画 | カメラは自分を追う。プレイヤー全員を描く(今は `P` を 1回)。名前と、画面の外にいる人への矢印。HUD は自分の分 |
| 時間を止める・遅くする | **3段で作った**: `hitstop(t, all)` / `slowmo(k, dur, all)`。2人以上の時は `all` の物だけ時間を止める・遅くする。印を付けたのはボスのファイル・`phase.js`・エリートとゴブリンの撃破の 39か所。倒れた時のスローは全員が倒れた時だけ。分け方は #5 |

## 3. ずれ(デシンク)の元と対策

同じ入力でも、ブラウザ・窓・設定で計算が変わる所。どれか 1つでも残るとずれる。

| ずれの元 | 今 | 対策 |
|---|---|---|
| 1フレームの長さ | 実時間(最大 1/30秒) | **1段で作った**: 1/60 秒ずつ進める形(`FIXED_STEP`。遅れた分は 4回までまとめて計算)。協力プレイの時だけ on(#23) |
| 乱数 | `Math.random` 1つを、計算・演出・効果音・画面が一緒に使う(`Math.random` 約 460か所、`rand / pick / shuffle` 約 1,460か所) | **1段で分けた**(`core.js`): `Math.random` は `simScope` の中(frame が update を包む)では計算の列(mulberry32。種は `simSeed`。協力プレイでは部屋の種)、外では見た目の列。描画は `fxScope`。効果音(実時間で間引く)・技の演出(skillfx)・宝箱の画面・カメラの揺れは見た目の列。**まだ**: ランの始め・レベルアップのカードを選ぶ・リロールなど画面から呼ぶ物は見た目の列で引く(1人用では困らない。3段・5段で入力として計算の中へ)。ランの終わりの装備の報酬は計算の列で引くので、協力プレイでは全員の引きがそろう(各自の報酬をどの列で引くかは 5段で決める) |
| 設定で変わる処理 | 粒(`part`)はグラフィック品質で間引くときに `Math.random` を引く。火炎放射の炎・乱れ桜の流れる斬撃・アローレインの見た目の矢・リフトの裂け目は、数が画質・攻撃の濃さで変わる | **1段で直した**: どれも見た目の列で引く(`fxScope` / `frand` / `fpick`)。画素なしのハッシュは、攻撃の濃さ 0.15 / 1・描画あり / なしで同じ。画質で違うのはエレクトロだけ(下のカメラの行) |
| 実時間のタイマー | `setTimeout` 27か所(計算に関わるのは 14か所) | **1段で直した**: 計算の 14か所は `simTimeout`(update の最後に進む。ポーズ・レベルアップの間は止まり、ランが変わると捨てる)。画面だけの物(ui.js・gacha.js・meta-ui.js)は setTimeout のまま。通しのハッシュは前と同じだった |
| 画面の大きさ | `GFX.VW / VH` は窓に合わせて変わり、計算で 85か所使う(出現の距離など)。1段の確かめでも、窓の大きさが違うと画素なしのハッシュが違った | **2段で直した**: 協力プレイの形(`SIM_VIEW.on`)では、計算の間だけ `GFX.VW / VH` を計算用の大きさに入れ替える(#16)。1人用は今までどおり窓の大きさ |
| カメラ | `cam` はなめらかに追い・揺れ・照準でずれる。計算で 174か所使う(`onScreen` 13か所・ボスの技の位置など)。1段で、エレクトロの Q の塔(`cam.x + rand(…)` に置く)が画質で違うのを見つけた(揺れが見た目の列で決まり、その列を粒の間引きも引くため。揺れを止めると同じ) | **2段で直した**: 協力プレイの形では、計算の間だけ `cam` を「自分が真ん中の、揺れない四角」に入れ替える(`core.js` の `simView`。描画は本当のカメラのまま)。計算の中で画面の位置に直す所は `shockAt` だけで、そこは本当のカメラを使う。1人用は今までどおり。3段で `P` を入れ替える時は、四角もその人に合わせる |
| マウス照準 | `mouseAimPt()` はその人の画面のマウス | **2段で直した**: 入力の記録を取る時にワールドの座標にする(`P.inp.aim`)。`mouseAimPt()` はそれを返す |
| 三角関数など | ゲームが使う `Math.sin / cos / tan / atan / atan2 / asin / hypot / pow / exp`(約 2,100か所)は、ブラウザの JS エンジンで最後の 1桁が違う(7章 0段で確かめた。400個の入力で `hypot` は約 37%、`atan2` は Firefox で約 18%、`sin` は約 2% が違う。`sqrt`・整数の累乗・`round / floor / abs / min / max` は同じ)。今のままだと試験の通しは最初のボスの回からずれる | 足し算・掛け算などだけで計算する版(`js/detmath.js`。係数は fdlibm)に置き換えると、Chromium / Firefox / WebKit で通しのハッシュが同じになった。ネイティブとの差は相対 2〜4e-16(小数乗の `pow` は 6e-15)。**1段でゲームに入れた**(#22)。`**` は置き換えが効かない(エンジンの累乗)ので `Math.pow` に(11か所) |
| 見た目のための処理 | 描画が計算の状態を書き換えていないか | **1段で確かめた**: 描画あり / なしで、画素なしのハッシュが同じ |

## 4. 通信

| 項目 | 作り方 |
|---|---|
| つなぎ方 | WebRTC のデータチャンネル(ブラウザどうしで直接)。ホストが中心で、ほかの人はホストとだけつなぐ。ホストは受けた入力をほかの人へ配る |

| TURN | 最初は無し(#19) |
| 送る物 | 参加: 名前・ゲームの版・クラス・セーブのうちステータスに要る物 / 開始: 乱数の種・開始のフレーム / 毎フレーム: 入力 / 1秒ごと: 状態のハッシュ / 抜けた・切れた |

| 開発用 | 同じブラウザの 2つのタブでつなぐ仮の通信(BroadcastChannel)。外部のサービスなしで、試験の道具から 2画面を動かし、毎フレームのハッシュを比べる |

## 5. 共有 / 個別

`tower.md` 3章の分け方に、計算と画面の分け方を足したもの。

| 共有(全員で同じ計算) | 個別(1人ずつ。計算に入れない物は「画面」) |

| 全員のプレイヤーの位置・HP・状態異常 | 画面: カメラ・HUD・設定(品質・音量・言語・UI の大きさ・攻撃の濃さ) |
| 床に落ちている物(早い者勝ち。#6)・敵の狙いと与えたダメージの記録(#14) | セーブ・報酬(ゴールド・クラス経験値・装備は各自のセーブに入る) |
