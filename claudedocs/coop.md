## 1. 同期の方式: ロックステップ

全員のブラウザが同じゲームを同じ乱数で計算し、送り合うのは毎フレームの入力だけにする。

- 各フレームは「全員のそのフレームの入力」がそろってから計算する。入力は数フレーム先の分として送る(入力の遅れ。#1)ので、回線が普通なら待たずに進む
- 送るもの: 移動の向き・E・Q・防御・照準の点・レベルアップのカードの選択。数十バイト / フレーム
- 演出・音・数字は、全員が同じ計算をするので、そのまま全員の画面に出る(送らない)
- 1秒ごとに状態のハッシュを送り合い、ずれ(デシンク)を見つける(#4)

この方式にした理由:
- 試験の道具(`scripts/dev/harness.js`)が、乱数の固定・setTimeout をゲームの時間で動かす・1/60 秒ずつ進める・描画の乱数を計算と分ける、をすでにやっていて、同じ入力なら同じハッシュになる。今の計算は、この方式の条件をほぼ満たしている
- ホストが計算して状態を送る方式は、描画(`render.js`・各ボスの描画)が敵の AI の中身まで読み、演出も計算の中で作っているので、送る物がほぼ世界全部になる

弱いところ:
- 操作が少し遅れる(#1)
- 1人の回線が詰まると全員が止まる(#3)
- 途中参加はできない(#12)
- 全員が全員の分を計算するので、4人だと 1人のときより重い(スマホが心配。8章)

## 2. 今のコードでの作り方

| 仕組み | 作り方 |
|---|---|
| プレイヤー | `players`(1〜4人)。`P` は「いま計算しているプレイヤー」(`P.` は約 3,800か所あるので書き換えない)。自分の分の処理(`updPlayer`・`updWeapons`・クラス)は、`P` を入れ替えて人数分回す |
| 敵の狙い | 敵ごとに狙う人(`e.tgt`)を持ち、敵・ボスを計算する前にその人を `P` にする(これらのファイルで `P.x / P.y` は約 280か所)。選び直しは #14。敵の弾・床は作った時の狙う人を持ち、追う物はその人を追う |
| 与えたダメージの記録 | 敵ごとに人ごとのダメージ(`e.dmgBy`)を持ち、`hitEnemy` の時の `P`(撃った人)に足す。燃焼・毒など後から入るダメージは、付けた人を重ねごとに持たせる。#14 の重みに使う |
| 拾うもの | 床の物は 1つ(`gems`・`drops` は共有)。毎フレーム、プレイヤーの番号順に全員と距離を見て、先に届いた人が拾う(同じフレームなら番号の小さい人)。吸い寄せは、吸い寄せる範囲に先に入った人へ向かう。ジェム・ゴールドは `P` を入れ替えて全員に `gainXP`・`addGold` を呼ぶ。#6 |
| 当たり判定 | 敵の弾・床・体当たりは全員と判定する(`P` を入れ替えて `hurtPlayer`) |
| `S` にある 1人ずつの物 | `P` へ移す: コンボ・ゴールド・撃破数・与えたダメージ・レベルアップの待ち(`pendingLv`・`lvQueue`・`lvFx`)・リロール・武器枠・クラス経験値の元(`cxpK`・`cxpB`)・手に入れた装備・回復量・クラスの物(氷の分身 `decoy`・聖痕・炎の煙・`actId`)・HUD の書き直し |
| 入力 | `keys`・`touch`・`mouse` を 1人分の入力の形 `{ mx, my, e, q, def, aim, pick }` にまとめ、計算は入力の形だけを読む(今は `moveInput()`・`keys._e / _q`・`keys.Space / TouchDef`・`mouseAimPt()`) |
| ステータス | 参加の時に各自の クラス・クラスLv・武器・強化ツリー・装備 を送り合い、全員が全員のステータスを計算する(`applyStats` を「その人のセーブ」で) |
| レベルアップ | 止まらない画面(#8)。カードの選択は入力として送り、全員が同じフレームで適用する |
| 描画 | カメラは自分を追う。プレイヤー全員を描く(今は `P` を 1回)。名前と、画面の外にいる人への矢印。HUD は自分の分 |
| 時間を止める・遅くする | `hitstop` / `slowmo` を呼ぶ所は約 70行。全員に関わる物にだけ印を付け(`hitstop(t, true)` のように。約 35行)、協力プレイでは印の付いた物だけ時間を止める・遅くする。分け方は #5。`FX_MINE`(自分の攻撃の印)では分けない(エリートの撃破は撃った人の攻撃の処理の中で起きるので、1人の物に見えてしまう) |

## 3. ずれ(デシンク)の元と対策

同じ入力でも、ブラウザ・窓・設定で計算が変わる所。どれか 1つでも残るとずれる。

| ずれの元 | 今 | 対策 |
|---|---|---|
| 1フレームの長さ | 実時間(最大 1/30秒) | 1/60 秒に固定し、遅れた分は何フレームかまとめて計算する |
| 乱数 | `Math.random` 1つを、計算・演出・効果音・画面が一緒に使う(`Math.random` 約 460か所、`rand / pick / shuffle` 約 1,460か所) | 計算用の乱数を部屋の種で作る。効果音(`AudioMan`。実時間で間引くので引く回数が人によって違う)・画面・描画は別の乱数 |
| 設定で変わる処理 | 粒(`part`)はグラフィック品質で間引くときに `Math.random` を引く | 間引きの判定は別の乱数で(品質の設定が違ってもずれない) |
| 実時間のタイマー | `setTimeout` 27か所 | ゲームの時間で動くタイマーに(試験の道具の fakeST と同じ考え) |
| 画面の大きさ | `GFX.VW / VH` は窓に合わせて変わり、計算で 85か所使う(出現の距離など) | 計算の間だけ 480×270 に固定する(#16) |
| カメラ | `cam` はなめらかに追い・揺れ・照準でずれる。計算で 174か所使う(`onScreen` 13か所・ボスの技の位置など) | 計算の間は「いま計算しているプレイヤーが真ん中の、揺れない四角」にする |
| マウス照準 | `mouseAimPt()` はその人の画面のマウス | ワールドの座標にして入力として送る |
| 三角関数など | `Math.sin / cos / atan2 / hypot / pow / exp` など約 2,100か所。ブラウザの JS エンジン(Chrome / Firefox / Safari)で結果が少し違うことがある | **未確認**。7章の 0 で比べる。ずれるなら、足し算・掛け算だけで書いた同じ計算に置き換えるファイルを 1つ足す |
| 見た目のための処理 | 描画が計算の状態を書き換えていないか | 1人用のまま、描画あり / なしでハッシュを比べて確かめる |

| 項目 | 作り方 |
|---|---|
| つなぎ方 | WebRTC のデータチャンネル(ブラウザどうしで直接)。ホストが中心で、ほかの人はホストとだけつなぐ。ホストは受けた入力をほかの人へ配る |

## 5. 共有 / 個別

`tower.md` 3章の分け方に、計算と画面の分け方を足したもの。

| 共有(全員で同じ計算) | 個別(1人ずつ。計算に入れない物は「画面」) |
|---|---|
| 階・撃破数・闇の霧の時計・休憩 | 貯蓄経験値・経験値・レベル・レベルアップのカード |
| 敵・ボス・敵の弾・床(HP は人数の倍率) | 武器・ステータス(各自のセーブから) |
| ステージ・カオス強化・計算用の乱数 | ジェム・ゴールドで得る量(各自の倍率。#6) |
| 全員のプレイヤーの位置・HP・状態異常 | 画面: カメラ・HUD・設定(品質・音量・言語・UI の大きさ・攻撃の濃さ) |
| 床に落ちている物(早い者勝ち。#6)・敵の狙いと与えたダメージの記録(#14) | セーブ・報酬(ゴールド・クラス経験値・装備は各自のセーブに入る) |

## 7. 進め方

どの段も、1人用のまま試験のハッシュが変わらない(または、変わる理由が分かっている)ことを確かめてから次へ。

| 段 | やること | 確かめ方 |
|---|---|---|
| 0 | Firefox・WebKit を入れて、`classSmoke`・`bossSmoke` のハッシュを Chromium と比べる(今の手元は Chromium だけ) | 同じなら 3章の三角関数は対策不要。違えば置き換えのファイルを足して、もう一度比べる |
| 1 | 1フレームを 1/60 秒に固定・計算用の乱数と効果音・画面・描画の乱数を分ける・タイマーをゲームの時間に・粒の間引きを別の乱数に | 1人で遊んで手触りが変わらないこと。ハッシュは乱数を分けた分だけ変わる(変わったあとの値を新しい基準に) |
| 2 | 入力を 1人分の形にまとめる・計算用のカメラと画面の大きさ | 1人用のままハッシュが同じ |
| 3 | `players` と `P` の入れ替え・`S` の 1人ずつの物を `P` へ・敵の狙いの選び直し(`e.tgt`・`e.dmgBy`。#14)・床の物の共有(#6)・ヒットストップの印(#5) | 1人用のままハッシュが同じ(1人なら狙いはいつもその人、拾う物の決まりは協力プレイだけ) |
| 4 | 2つのタブを仮の通信でつないで 2人 | 試験の道具で 2画面を動かし、毎フレームのハッシュが同じ |
| 5 | 画面: 止まらないレベルアップ・ほかの人の描画と演出の薄さ(#21)・観戦・休憩の待ち・部屋の画面と公開ロビー(#10) | 2タブで遊ぶ |
| 6 | Supabase の仲介と WebRTC・版の確認 | 別の端末どうし(PC とスマホ)でつなぐ |
| 7 | 4人・スマホが混ざった試験 | 重さ・ずれ・つながらない率 |
